# ZenArt Stage 0 草案

日期：2026-05-26

## 0. 结论先行

ZenArt 不应该被定义成泛 AI 绘图工具、PPT 编辑器、Figma 替代品、广告投放平台、游戏资产生产管线、CAD/BIM 工程工具，或法律/医疗/金融专业建议系统。

Stage 0 最准确的定位是：

> ZenArt 是一个 AI 画布式视觉设计工作台。用户从 chatbox 输入目标，agent 把目标拆成 4 个明显不同的方案，用户 4 选 1 后继续在无限画布上迭代，最后把选中的结果从左侧打包带走，形成可下载、可复用、可交付的视觉资产包。

前台体验必须统一且简单：

- 一个 chatbox 入口，不让用户学习 prompt 或工具菜单。
- 一个无限画布，承载参考、候选、分支、成品和交付包。
- 每轮 4 选 1，帮助用户做决策，而不是随机多出几张图。
- 左侧打包带走，把图片变成业务资产包。
- 行业 skill 全部隐藏在后台，只负责路由、规划、质量检查、导出和安全边界。

后台 skill 可以非常垂直、非常业务化；前台不要暴露成技能市场。用户只表达目标，系统判断该走哪个工作流。

## 1. 本轮 10 个高推理辩论视角

本草案综合了 10 个 GPT-5.5 high 代理视角：

| Agent | 视角 |
|---|---|
| 1 | 创意设计、品牌、营销 |
| 2 | 企业办公、PPT、销售赋能、咨询 |
| 3 | 游戏、动漫、角色、IP 资产 |
| 4 | 电商、广告投放、社媒增长、直播带货 |
| 5 | 教育、知识可视化、课程设计 |
| 6 | 产品设计、Figma、UX/UI、设计系统 |
| 7 | 建筑、室内、地产、空间设计 |
| 8 | 法律、金融、医疗、合规敏感行业 |
| 9 | 工业、制造、供应链、硬科技 |
| 10 | 本地生活、餐饮、小商家、文旅、空间营销 |

共识很明确：

- 核心闭环应是 `brief -> 4 options -> choose 1 -> iterate -> QA -> package -> export`。
- 4 个候选必须代表 4 种业务策略或表达路径，不是同图换色。
- 左侧面板必须是资产包/交付包系统，不只是历史记录。
- Stage 0 最适合先验证高频、可交付、有付费理由的视觉生产场景。
- 法律、医疗、金融、工程安全、合规认证等敏感行业只能做视觉草稿和教育图解，不能做专业建议或最终交付。

争议也很清楚：

- 企业/PPT/咨询派认为 ZenArt 应先做可交付商业材料。
- 电商/营销派认为 3500 图/周最适合广告素材矩阵、商品图、详情页、直播贴片。
- 游戏/IP 派认为 4 选 1 和无限画布最适合角色、皮肤、道具、世界观探索。
- 本地生活派认为最容易付费和留存的是餐饮、小商家每周活动物料。
- UX/Figma 派认为 ZenArt 不应被任何垂直捕获，核心是 AI-native design workspace。

综合判断：Stage 0 应公开聚焦“AI 画布式视觉设计工作台”，内部用少数高频垂直工作流证明价值，而不是一上来宣称全行业解决方案。

## 2. 产品主张

大多数用户不想学 Figma、Photoshop、Midjourney 参数、Canva 模板、PPT 版式、平台尺寸、广告素材规则、电商详情页结构、咨询框架或行业图解规范。用户真正想要的是：把一个业务目标快速变成能发、能卖、能汇报、能展示、能继续改的视觉资产。

ZenArt 要把专家过程藏起来：

| 用户说 | 系统后台应做 |
|---|---|
| “给这个护肤品做小红书上新包。” | 识别平台、商品、卖点、功效风险、尺寸、视觉钩子，生成 4 个方向和导出包。 |
| “帮我给制造业客户做一份 AI 质检销售方案。” | 生成提案结构、流程图、架构图、ROI 页、实施路线图，并打包 PPT-ready/PDF。 |
| “做一个赛博唐风女剑客，适合二次元手游。” | 建立角色记忆，生成 4 个角色方向，扩展服装、武器、表情、宣发图。 |
| “给咖啡店本周新品做朋友圈、小红书、外卖头图和 A4 海报。” | 解析菜品、价格、活动、渠道，生成 4 个用途版本并输出多尺寸包。 |
| “解释我们的 MES + WMS + IoT 工厂方案。” | 生成数字化架构、流程、数据流、阶段路线图、客户版一页纸。 |

产品目标不是让用户操作复杂工具，而是让用户做少量高质量决策。

## 3. 统一交互模型

### 3.1 工作台布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：项目名 / 套餐 / 本周额度 / 分享 / 导出                  │
├────────────────┬────────────────────────────┬────────────────┤
│ 左侧面板       │ 无限画布                   │ 右侧面板       │
│                │                            │                │
│ Chat / brief   │ 4 选 1 候选组              │ 属性           │
│ 任务           │ 已选 frame                 │ 风格锁         │
│ 资产库         │ 分支 / 参考 / 版本         │ 图层           │
│ 打包带走       │ 工作板 / 交付区            │ QA             │
│ 导出           │ 缩略地图 / 缩放            │ 元数据         │
└────────────────┴────────────────────────────┴────────────────┘
```

建议默认：左侧包含 chat、任务、资产包和导出；右侧包含属性、风格、图层和 QA；中间无限画布是主舞台。

### 3.2 4 选 1 的原则

4 个候选必须有明确差异：

| 场景 | 4 选 1 应代表什么 |
|---|---|
| 品牌 | 高级克制、年轻社媒、编辑感、转化导向 |
| 电商 | 转化版、生活方式版、功能证明版、促销版 |
| PPT/销售 | 高管摘要、方案架构、ROI 叙事、实施路线 |
| 本地商家 | 微信成交、小红书质感、门店打印、平台封面 |
| 游戏/IP | 可爱、英气、暗黑、华丽；或角色、服装、道具、场景方向 |
| 工业 | 老板版、客户版、工程师版、操作员培训版 |
| 空间设计 | 收纳优先、通透动线、家庭生活、出片效果 |

不要做“同一张图换四个颜色”。每个选项都要说明适合什么用途，帮助用户决策。

### 3.3 左侧打包带走

左侧打包带走是商业闭环，不能只是“下载图片”。

必须支持：

- 把选中的候选加入资产包。
- 按业务用途分组，而不是只按文件格式分组。
- 导出前运行 QA。
- 导出 ZIP、PNG/JPG、PDF、PPT-ready、Figma-ready spec、分享链接。
- 带上 prompt 记录、版本说明、尺寸清单、风险标签和需要人工确认的项目。

示例：

```text
Package: 护肤品上新
- 选中方向：Clinical clean / social proof
- Assets
  - hero_4x5.png
  - xiaohongshu_cover.png
  - detail_ingredients.png
  - live_price_badge.png
  - meta_ad_1x1.png
  - tiktok_ad_9x16.png
- Specs
  - sizes.json
  - copy_variants.md
  - prompt_log.md
  - qa_report.md
- Export
  [Download ZIP] [Copy to Figma] [Share review link]
```

## 4. Stage 0 行业优先级

Stage 0 不建议讲“覆盖所有行业”。建议公开先证明 3 条 P0 商业主线，再保留 1 条创意展示主线。

### 4.1 P0 主线 A：交易型视觉生产

覆盖电商、广告投放、社媒增长、直播带货。

为什么优先：

- 高频、刚需、可批量。
- 3500 图/周价值最容易被理解。
- A/B 测试、多尺寸、多平台、多 SKU 都需要大量变体。
- 左侧打包带走价值很直观：商品包、广告包、直播包、社媒包、跨境包。

目标用户：

- 电商运营。
- DTC 品牌。
- 广告投放师。
- 社媒增长团队。
- 直播电商团队。
- 跨境卖家。

首批细分行业：

| 优先级 | 细分行业 | 原因 |
|---|---|---|
| P0 | 美妆个护/护肤彩妆 | 高毛利、高视觉需求、高投放需求；需强功效宣称护栏。 |
| P0 | 服饰鞋包/配饰 | SKU 多、季节变化快，适合 lookbook、穿搭、社媒图。 |
| P0 | 食品饮料/日化/母婴 | 包装、口味、信任和促销图需求强；需合规词检查。 |
| P0 | 家居百货/小家电/3C 配件 | 功能图、使用场景图、安装说明、详情页需求稳定。 |
| P0 | 跨境电商 | 多平台、多语言、多文化风格、多尺寸适配。 |

核心工作流：

| 工作流 | 输出 |
|---|---|
| 商品主图 | 白底图、场景图、套装图、细节图、尺寸图。 |
| 详情页 | 6-10 个模块：利益点、痛点、功能、对比、参数、FAQ。 |
| 广告素材矩阵 | 1:1、4:5、9:16、16:9；hook、CTA、人群、投放阶段。 |
| 短视频分镜 | 3 秒 hook、问题场景、产品出现、卖点证明、福利、CTA。 |
| 直播间贴片 | 价格条、福利条、倒计时、爆品卡、直播背景、透明 PNG。 |
| 社媒种草包 | 小红书封面、九宫格、UGC 风格图、达人脚本画面。 |
| 大促活动包 | 618、双 11、黑五、圣诞、情人节、返校季等节点。 |

后台隐藏 skill：

- 商品主体保护。
- 平台尺寸适配。
- 功效/禁用词/敏感类目护栏。
- 详情页信息架构。
- 广告策略生成。
- 直播贴片安全区。
- 跨境多语言和文化风格迁移。
- 多格式导出打包。

边界：

- 不编造产品功效、认证、评价、销量、前后对比。
- 未经用户明确允许，不改变商品主体、logo、形状、颜色和材质。
- 美妆、食品、保健、母婴等类目必须自动进入风险检查。

### 4.2 P0 主线 B：商业视觉文档

覆盖 PPT、销售提案、咨询交付、工业视觉沟通。

为什么优先：

- 用户必须交付材料，不只是娱乐式生图。
- 销售、咨询、汇报、售前愿意为效率付费。
- 4 选 1 可以代表不同叙事策略，而不是审美抽奖。
- PPT-ready/PDF/Figma-ready 打包价值强。

目标用户：

- 创始人。
- 销售和售前。
- 咨询顾问。
- 产品市场。
- SaaS 和硬科技团队。
- 制造/供应链/工业软件团队。

核心工作流：

| 工作流 | 输出 |
|---|---|
| 一句话生成 deck | 大纲、4 套视觉/叙事方向、选中后扩展页面。 |
| 文档转 PPT | 提炼结论、拆页、路由页面类型、生成图表和图解。 |
| 丑 PPT 美化 | 保留内容，重构层级，生成 4 个版式方向。 |
| 销售提案 | 封面、痛点、方案、能力映射、ROI、案例、下一步。 |
| 咨询框架 | 问题树、矩阵、路线图、组织/流程模型。 |
| 数据转图表页 | 图表选择、洞察标题、高管汇报页。 |
| 工业解决方案图 | 流程图、产线图、架构图、手册图、客户一页纸。 |

工业/硬科技子线：

| Skill | Stage 0 范围 | 边界 |
|---|---|---|
| 工业流程图 | 流程、泳道、价值流风格、数据流 | 不做工程图纸。 |
| 产线概念图 | 工站顺序、物流、人机协作、检测点 | 不作为 CAD、安装、安全依据。 |
| 设备说明图 | 部件标注、操作步骤、维保流程 | 部件和警示需用户确认。 |
| 数字化工厂架构 | MES/WMS/ERP/IoT 集成、数据链路、看板 mockup | 不编造技术参数。 |
| 产品手册包 | 快速入门、安装步骤、多语言插图 | 不替代官方 IFU 或合规文件。 |
| 售前方案包 | 现状痛点、目标方案、路线图、价值说明 | ROI 需用户提供或标记估算。 |

后台隐藏 skill：

- Deck planner。
- Slide type router。
- Business layout generator。
- Consulting framework router。
- Diagram semantic planner。
- 工业符号库。
- 面向不同受众的 4 选 1。
- PPT/PDF/Figma-ready packager。

边界：

- ZenArt 可输出 presentation-ready visual pack，但不替代 PowerPoint/Keynote。
- ZenArt 可输出工业沟通图，但不替代 CAD、工程设计、安全评估、施工图、安装图、监管文件或认证材料。

### 4.3 P0 主线 C：本地商家与空间营销

覆盖餐饮、本地生活、小商家、文旅、民宿、商业地产招商、空间风格板。

为什么优先：

- “今天就要发图”的需求非常明确。
- 小团队没有设计师，不想学工具。
- 一次活动天然需要多渠道资产包。
- 无限画布可以承载活动、素材、渠道尺寸、历史版本和已导出文件。

目标用户：

- 餐厅、咖啡、奶茶、烘焙、小吃。
- 美甲、美发、美容、健身、宠物、教培、维修、摄影等本地服务。
- 民宿、酒店、景区、文旅公司、小旅行社。
- 商业地产、街区运营、园区招商。
- 室内设计、软装、家居品牌的前期提案和销售图。

核心工作流：

| 工作流 | 输出 |
|---|---|
| 菜单/新品卡 | A4 打印、朋友圈、小红书、外卖头图、价格卡。 |
| 门店活动海报 | 开业、会员日、节日、新品、团购、周末活动。 |
| 价目表/套餐卡 | 服务项目、价格、权益、预约信息。 |
| 社媒多尺寸包 | 小红书、朋友圈、微信群、抖音封面、门店打印。 |
| 文旅路线包 | 路线图、打卡点卡片、时间轴、九宫格、长图攻略。 |
| 民宿/酒店套餐 | 房型、周边玩法、节假日活动、导览图。 |
| 商业招商图 | 区位、客流、业态规划、客群画像、招商海报、路演页。 |
| 空间风格板 | 材质、色彩、灯光、家具、门头、拍照点。 |

4 选 1 应按用途分：

| 版本 | 用途 |
|---|---|
| 促销转化版 | 字大、价格大，适合微信群和朋友圈。 |
| 品牌质感版 | 更干净高级，适合小红书和门店形象。 |
| 门店打印版 | 信息清楚，适合 A4/A3/桌牌/门贴。 |
| 平台封面版 | 适合外卖、团购、抖音、小红书封面。 |

后台隐藏 skill：

- 中文商业文案结构。
- 菜单/价格/活动解析。
- 平台尺寸路由。
- 轻量品牌资产记忆。
- 节日营销日历。
- 二维码/电话/日期/价格 QA。
- 手机发布版与打印版分离。
- 本地商家多渠道打包。

边界：

- 价格、日期、电话、地址、二维码不能靠图片模型生成，应使用结构化文字图层。
- 对小商家不要强调“3500 图/周”，前台卖点应是“一次活动，全渠道物料包”。

### 4.4 P0 展示主线：游戏、动漫、角色、IP 探索

这条线适合展示产品魅力，但 Stage 0 不应承诺专业游戏资产管线。

保留原因：

- 4 选 1 非常适合角色、皮肤、道具、场景。
- 无限画布很适合角色设定板、资产板、世界观板。
- 3500 图/周对创作者有直观吸引力。
- 可以展示 agentic 绘图不是只会做商业海报。

Stage 0 范围：

| Skill | 可支持 |
|---|---|
| OC/角色创建 | 4 个角色方向、角色记忆、头像、半身、表情。 |
| 服装/皮肤变体 | 保持同一角色，换主题、衣服、武器、配色。 |
| 道具/武器/图标 | 成套概念板和批量变体。 |
| 场景 moodboard | 氛围、局部、世界观视觉板。 |
| 角色宣发图 | 横版/竖版/方图，无字版，标题安全区。 |
| 卡牌/VN/漫画轻量支持 | 做概念图和单页方向，不做完整编辑器。 |

边界：

- 不承诺 Unity/Unreal-ready 资产。
- 不承诺 Spine、Live2D 拆件、绑定、动画、LOD、引擎导入。
- 不支持复制现有 IP、在世艺术家风格、受保护品牌风格。

## 5. P1/P2 扩展

### 5.1 P1

| 扩展 | 原因 |
|---|---|
| 品牌视觉系统 | 支撑电商、本地商家、社媒、活动物料。 |
| 空间设计项目板 | 室内风格板、软装、地产销售物料、客户提案包。 |
| 教育/知识可视化 | 课程封面、培训 PPT、知识卡片、信息图。 |
| 资产管理 | 标签、搜索、参考、版本、已选/弃用。 |
| 轻协作 | review link、评论、只读分享。 |
| Brand kit | logo、颜色、字体、语气、二维码、联系方式。 |
| Design QA | 文字、尺寸、品牌一致性、缺失素材、导出完整性。 |

### 5.2 P2

| 扩展 | 延后原因 |
|---|---|
| 模板/市场 | 先证明工作流，否则容易变成模板堆。 |
| 深度游戏生产管线 | 需要一致性、格式、引擎约束。 |
| CAD/BIM/建筑深度集成 | 需要专业精度和责任边界。 |
| 法律/医疗/金融行业产品 | 需要合规、审核链、审计、企业控制。 |
| 高端完整 VI | 高定制、高审美、高人工审核。 |
| 专业电商详情页全流程 | 需要商品保真、平台规则、法务审核、质量控制。 |

## 6. 隐藏 Skill 架构

用户不选择 skill，系统内部路由：

```text
用户目标
  -> 意图识别
  -> 行业/工作流路由
  -> brief 补全
  -> 4 选 1 策略生成
  -> 画布布局规划
  -> 出图与修订
  -> 领域 QA
  -> 打包导出
  -> 额度结算
```

### 6.1 Skill 家族

| Skill 家族 | 作用 |
|---|---|
| Brief intelligence | 把模糊输入转成用途、受众、渠道、限制条件。 |
| Creative direction | 生成有差异的方向，并解释取舍。 |
| Layout intelligence | 选择 frame、层级、留白、安全区和布局。 |
| Domain workflow | 电商、PPT、本地商家、游戏/IP、工业、空间、教育等。 |
| Design memory | 记住选中风格、被拒方向、品牌资产、角色/世界观约束。 |
| Canvas governance | 自动分组、命名、折叠、标记、整理画布。 |
| Decision support | 解释 4 个方案适合什么，降低选择成本。 |
| QA and safety | 检查文字、尺寸、功效宣称、风险标签、导出完整性。 |
| Handoff/package | 生成可接手资产包、元数据、规格和版本说明。 |
| Quota economy | 预估消耗、草稿/高清模式、失败返还、批量模式。 |

### 6.2 前台用语

不要让用户看到：

- “选择 product-preservation skill。”
- “运行 slide-type-router。”
- “启用 consulting-framework-router。”
- “调用 regulated_visual_assistant。”

应该让用户看到：

- “做一套商品上新包。”
- “把这段内容变成客户方案。”
- “生成 4 个菜单和海报方向。”
- “保持这个角色，只换衣服。”
- “改成老板能看懂的版本。”
- “打包成小红书、朋友圈、打印版和 PDF。”

## 7. 套餐和额度

Stage 0 商业假设：

- 订阅：`$20/month`。
- 周限额：`3500 images/week`。
- 这不是玩具式图片额度，而是生产型视觉工作流订阅。

### 7.1 额度 UX

| 状态 | 要求 |
|---|---|
| 生成前 | 显示预计消耗。 |
| 草稿模式 | 低成本探索，默认用于早期 4 选 1。 |
| 高清模式 | 用户明确消耗更多额度换最终图。 |
| 批量模式 | 电商/广告矩阵/活动包使用。 |
| 余额不足 | 提醒并建议缩小范围。 |
| 失败生成 | 明确定义是否返还额度。 |
| 周重置 | 显示重置日期和剩余额度。 |
| 项目用量 | 显示哪个项目/包消耗最多。 |

### 7.2 不同用户的额度包装

| 用户 | 不要这么卖 | 应该这么卖 |
|---|---|---|
| 电商/广告团队 | “3500 张随机图” | “支撑 SKU x 人群 x 渠道的素材测试矩阵。” |
| 本地商家 | “3500 张图” | “一次活动，自动生成全渠道物料包。” |
| PPT/销售 | “图片数量” | “客户可交付的方案视觉包。” |
| 游戏/IP 创作者 | “图片数量” | “足够迭代角色、皮肤、道具、场景。” |
| 工业用户 | “图片数量” | “快速生成流程、手册、售前资料包。” |

## 8. Design QA 与导出

ZenArt 要通过 QA 和交付能力区别于普通生图工具。

### 8.1 QA 项

| QA 类型 | 检查内容 |
|---|---|
| 视觉 | 裁切、重叠、异常空白、主体偏移、一致性。 |
| 尺寸 | 比例、平台尺寸、安全区、手机/打印分离。 |
| 文字 | 乱码、不可读、电话/日期/价格错误、字号过小。 |
| 品牌 | 颜色、logo、风格漂移、系列一致性。 |
| 领域 | 功效风险、禁用词、工业参数幻觉、敏感行业标签。 |
| 画布 | frame 命名、版本关系、已选/弃用、资产包归属。 |
| 导出 | 缺文件、命名错误、缺参考、包不可用。 |
| Figma/PPT | 是否只有扁平图，是否有结构和规格元数据。 |

### 8.2 导出目标

| 导出 | Stage 0 要求 |
|---|---|
| PNG/JPG | 必做。 |
| PDF | 提案和打印包必做。 |
| ZIP | 必做。 |
| PPT-ready | 图片/布局包必做；完整可编辑 PPT 可延后。 |
| Figma-ready | frame/spec/assets/tokens；不替代 Figma。 |
| 分享链接 | P1 可实现，Stage 0 需定义。 |

## 9. 安全和合规边界

即使 Stage 0 不主打敏感行业，也必须有安全路由。

### 9.1 核心规则

ZenArt 可以帮助用户把已确认的信息画清楚、排好看、打包交付；不能替用户确认事实、给专业建议、做监管判断或产出专业最终文件。

### 9.2 敏感行业边界

| 领域 | 允许 | 禁止 |
|---|---|---|
| 法律 | 流程科普、律所营销草稿、合同结构图。 | 法律建议、诉讼策略、可签署法律文件、管辖区结论。 |
| 金融 | 金融教育图、预算概念、通用风险解释。 | 投资建议、交易信号、收益承诺、贷款/保险适当性判断。 |
| 医疗 | 健康科普、诊所流程、通用解剖教育图。 | 诊断、治疗、用药剂量、检查解读、医疗器械式功能。 |
| 合规 | 培训海报、政策解释、风险意识图。 | “已合规”判断、审计证据、监管申报、认证声明。 |
| 工业安全 | 安全意识图和用户提供的警示图。 | 安全验证、工程计算、安装/制造依据。 |

### 9.3 敏感导出声明

敏感导出包应附带可见元数据和声明：

> 本内容由 AI 辅助生成，仅用于视觉草稿、教育说明或营销初稿，不构成法律、医疗、金融、税务、投资、工程、安全或合规建议。发布、提交、诊疗、投资、签署、安装、制造、监管申报或商业依赖前，请由具备相应资质的专业人员审核。用户需自行确认事实、权利、数据来源、广告合规和第三方知识产权风险。

按领域追加：

- 医疗：不得用于诊断、治疗、用药、急救或替代医生意见。
- 金融：不构成投资建议、收益承诺、证券推荐或适当性判断。
- 法律：不建立律师-客户关系，不构成任何司法辖区法律意见。
- 版权：AI 生成内容的版权登记、排他性保护和第三方权利风险可能因地区和用途不同而变化。

### 9.4 禁止宣传

不要宣传：

- “默认合规”。
- “医疗级”。
- “律师级”。
- “投资顾问级”。
- “版权无忧”。
- “自动审计通过”。
- “FDA/SEC/HIPAA/GDPR certified”。

## 12. 端到端示例

### 12.1 电商上新包

用户：

> 这是一个新唇釉，帮我做小红书上新包和 TikTok Shop 直播促销素材。

系统：

1. 询问商品图、卖点、价格、人群、品牌调性。
2. 生成 4 个策略：成分信任、通勤妆感、节日礼盒、直播闪促。
3. 用户选 1 个。
4. Agent 扩展商品主图、详情页模块、社媒封面、直播贴片、广告比例。
5. QA 检查功效风险、文字字段、平台尺寸。
6. 左侧打包 social/ad/live/raw assets。

### 12.2 制造业销售方案

用户：

> 给食品工厂包装后段自动化升级做一套客户方案视觉包。

系统：

1. 解析现状痛点、目标效率、设备/系统、决策人。
2. 生成 4 个受众版本：高管价值版、客户架构版、工程流程版、操作培训版。
3. 用户选择高管 + 客户混合方向。
4. Agent 生成现状痛点图、目标流程、产线概念、ROI 视觉、实施路线图。
5. QA 标记 ROI 是用户提供还是估算。
6. 打包 PDF/PPT-ready 图和流程资产。

### 12.3 本地咖啡店活动包

用户：

> 山野咖啡本周上新杨梅冰美式 18 元，工作日第二杯半价，帮我做小红书、朋友圈、外卖头图和门店 A4。

系统：

1. 解析品名、价格、活动、渠道。
2. 生成 4 个用途版本：微信成交、小红书清爽、门店打印、外卖封面。
3. 用户选 1 个。
4. Agent 用结构化文字图层扩展所有渠道尺寸。
5. QA 检查价格、日期、电话、二维码。
6. 分别导出手机发布版和打印版。

### 12.4 角色/IP 概念包

用户：

> 做一个赛博唐风女剑客，适合二次元手游。

系统：

1. 提取身份、轮廓、服装、武器、配色、世界观标签。
2. 生成 4 个方向：冷艳、活泼、暗黑、华丽。
3. 用户选 1 个。
4. Agent 生成头像、半身、服装变体、武器特写、表情组、无字宣发图。
5. 打包角色设定板和原图资产。

## 15. 最终建议

Stage 0 应公开窄定位，内部宽能力。

公开定位：

> ZenArt 是一个 AI 视觉设计工作台。你用 chatbox 发起任务，从 4 个强方向里选 1 个，在无限画布上继续迭代，最后把可用资产打包带走。

内部定位：

> ZenArt 用隐藏 skill 把每个请求路由到电商、商业文档、本地商家、创意 IP、工业视觉沟通、空间营销、教育知识可视化和敏感行业安全边界。

Stage 0 第一阶段必须证明三件事：

1. 用户能从自然语言开始，而不是从模板开始。
2. 4 选 1 能帮助用户做真实业务/创意决策。
3. 左侧打包带走能把生成图变成值得每月付 20 美元的可交付资产包。
